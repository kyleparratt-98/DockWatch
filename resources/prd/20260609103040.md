## Original Requirements

Build a Python CLI tool that monitors local Docker container resource contention by scraping /sys/fs/cgroup and /proc filesystem metrics, extracts per-container CPU throttling, memory OOM scores, and I/O wait percentages, and visually outputs them to standard out using a real-time, color-coded ASCII heatmap grid with sparkline trends via the `rich` library's Layout and Panel widgets. It must handle edge-case scenarios where containers are ephemeral (PID recycling) or cgroup v2 paths differ from v1, falling back to `docker stats` API calls with graceful degradation and a warning banner.

docker_resource_monitor

## Product Goals

- Deliver real-time, intuitive visualization of Docker container resource contention
- Ensure robust operation across diverse Docker environments and edge cases
- Provide actionable insights to quickly identify performance bottlenecks

## User Stories

- As a DevOps engineer, I want to see a live, color-coded overview of all running containers' CPU, memory, and I/O stress so I can immediately spot which container is causing system slowdown.
- As a developer running local microservices, I want to monitor the resource trends of my ephemeral containers via sparklines to understand their behavior over time and debug intermittent performance issues.
- As a system administrator managing a shared development server, I need the tool to work reliably even when containers are frequently started/stopped (PID recycling) and automatically fall back to Docker API if direct filesystem access fails, with clear warnings.

## Competitive Analysis

- ctop: Terminal-based container metrics, simple list view, lacks detailed per-resource heatmaps and historical trends.
- Docker Stats CLI: Built-in `docker stats` command, provides raw numerical stream, no visualization or aggregation.
- Glances (Docker mode): General system monitor with Docker plugin, shows per-container stats but UI is not optimized for container-specific contention visualization.
- Prometheus + Grafana (with cAdvisor): Powerful for historical data and dashboards, but heavy setup, not real-time CLI, and requires a running service.
- Lazydocker: TUI for Docker management, includes logs and stats, but its focus is management over real-time, multi-metric contention heatmapping.
- Netdata (per-container charts): Real-time performance monitoring, can show container metrics, but is a full web dashboard, not a lightweight CLI tool.
- Weave Scope: Automatic discovery and visualization of containers, web-based UI, focuses on topology over detailed per-process resource contention metrics.

## Requirement Analysis

The core requirement is a Python CLI tool for monitoring Docker container resource contention. Key technical components include:
1. **Metrics Collection**: Scraping low-level system metrics from `/sys/fs/cgroup` (for CPU throttling, memory pressure) and `/proc` (for I/O wait). Must handle both cgroup v1 and v2 paths.
2. **Container Mapping**: Associating system PIDs and cgroups with Docker container IDs/names, handling ephemeral containers and PID recycling.
3. **Fallback Mechanism**: Gracefully degrading to the `docker stats` API (via Docker SDK) when direct filesystem access fails or is unavailable, with user notification.
4. **Real-time Visualization**: Using the `rich` library to create a dynamic, color-coded ASCII heatmap grid. Each cell represents a container and a metric (CPU, Mem, I/O).
5. **Trend Visualization**: Incorporating sparklines within the display to show metric trends over recent time intervals.
6. **Output Layout**: Organizing the display using `rich` Layout and Panel widgets for a structured, professional CLI interface.
7. **Performance & Robustness**: The tool must be efficient, not consume excessive resources itself, and handle edge cases (missing containers, permission errors) gracefully.

## UI Design draft

The CLI interface will be a full-screen, real-time updated display using `rich`.
- **Layout**: A main `Layout` split into a top `Panel` for a title/warning banner and a primary `Live` display area.
- **Primary Display**: A grid (table) where each row represents a Docker container (ID/Name). Columns represent metrics: CPU Throttling, Memory OOM Score, I/O Wait %. Each cell is a color-coded box (e.g., green->yellow->red based on severity) containing the current value and a small sparkline graph showing the trend of the last N data points.
- **Style**: Professional terminal style with borders, subtle colors for headers, and high-contrast colors for heatmap cells to indicate severity.
- **Interaction**: The tool runs continuously. Optional keyboard controls (e.g., 'q' to quit, 'f' to filter) could be added.
- **Fallback UI**: If falling back to Docker API, a distinct warning banner appears at the top, and the data source is indicated. The visualization may be simpler (e.g., no sparklines if historical data is limited).
